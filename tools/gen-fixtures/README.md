# gen-fixtures — golden protobuf bytes from the real Go code

Generates `crates/outh-core/tests/fixtures/golden.txt`: the exact protobuf
bytes gotohp produces (and accepts) for the fixed inputs shared with
`crates/outh-core/tests/protocol_fixtures.rs`.

## Why it exists

Outh's protocol layer is hand-rolled (CONTRACT.md §3) because the wire
bytes — not any schema library — are the compatibility contract with
Google's private endpoints. The Rust tests therefore check encoded bytes
against two independent derivations:

1. hand-computed bytes from `.proto/*.proto` field numbers +
   `core/api.go` construction code (constants in the Rust test file), and
2. this harness: the same messages marshalled by gotohp's own generated Go
   types (`app/generated`) with `google.golang.org/protobuf`.

If the two ever disagree, the Go bytes win — investigate the Rust side (or
the hand derivation) before regenerating.

## Running

Requires a Go toolchain (1.27 in the study sandbox) and a local clone of
gotohp. The clone is **not** vendored: `go.mod` has

```
replace app => /home/hatch/workspace/gotohp-study/gotohp
```

Adjust that path if the clone lives elsewhere. `GOPROXY=off` works if the
module cache already holds gotohp's dependencies (the study sandbox's
does); otherwise let it download.

```sh
cd tools/gen-fixtures
go run . > /tmp/golden-body.txt
# golden.txt = the 3 comment header lines + the generated body:
{ 
  echo "# Golden protobuf fixtures for Outh protocol tests."
  echo "# GENERATED by tools/gen-fixtures (Go, gotohp generated types @ 97a5dc0) — do not edit by hand."
  echo "# Regenerate: cd tools/gen-fixtures && go run . > ../../crates/outh-core/tests/fixtures/golden.txt (header lines must be re-added; see README)."
  cat /tmp/golden-body.txt
} > ../../crates/outh-core/tests/fixtures/golden.txt
```

Notes:

- `go mod tidy` warns about `github.com/google/go-cmp` (a test-only
  dependency of the protobuf module) if it is not in the module cache.
  It is not needed to build or run the harness.
- Values that `core/api.go` reads from the clock (album timestamps) are
  pinned to `1700000000` in both this harness and the Rust tests, so the
  output is reproducible. Everything else copies api.go's construction
  field-for-field, including the magic `46000000` and the `{1, 3}` trailer.
- The fixtures are synthetic (SHA-1 of the empty string, `deadbeef` token
  payload, example names). No real account data is involved.
